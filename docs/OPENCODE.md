# Работа с RustOS через OpenCode

Репозиторий содержит project-конфигурацию `opencode.json`. Она выбирает агента
`rustos-module`, добавляет правила RustOS в контекст и запрещает commit, push,
destructive Git, внешний filesystem, web, вложенных агентов и доступ к
локальному `.opencode/**`. Последний запрет не даёт глобальной конфигурации
перезаписать старый task mirror вопреки allowlist. Выбор модели и
provider остаётся пользовательской настройкой OpenCode: проект не привязан к
локальному адресу или секрету конкретной машины.

## Запуск

```bash
cd /path/to/rustos
opencode
```

Для автономного выполнения одного готового задания:

```bash
opencode run --agent rustos-module \
  "Выполни задание из docs/tasks/opencode-001-text-input-buffer.md"
```

Проверить, что project-конфигурация действительно загрузилась:

```bash
opencode debug config
opencode debug agent rustos-module
```

В resolved config `default_agent` должен быть `rustos-module`, а его `task`,
`webfetch`, `websearch` и `external_directory` — `deny`, а `.opencode/**`
запрещён для read/edit и shell. OpenCode читает
корневой `AGENTS.md` автоматически; `docs/OPENCODE.md` добавляется через
`instructions`. Ближайший каталоговый `AGENTS.md` агент обязан прочитать сам.

## Как выдавать работу небольшой модели

Одна сессия получает один наблюдаемый результат и allowlist из нескольких
файлов. Нельзя объединять ABI, service, DLL, приложение и установку в образ в
одном задании. Рекомендуемый шаблон:

```text
Цель: один результат, видимый тесту или пользователю.
Разрешено менять: точный список файлов/каталогов.
Запрещено: соседние подсистемы и существующие dirty files.
Прочитать: root AGENTS.md, ближайший AGENTS.md, один документ и код-аналог.
Контракт: типы, ошибки, capacity/lifecycle и намеренно отложенные возможности.
Acceptance: success + negative test и точные команды.
Отчёт: результат, тесты, git diff --name-only, ограничения.
```

Не начинайте с «перепиши Terminal», «доделай GPU» или «портируй Rust». Такие
цели разбиваются на короткие зависимости из `docs/OPENCODE_BACKLOG.md`.

## Контроль результата

После каждой сессии владелец change должен прочитать весь diff, сверить список
файлов с allowlist и самостоятельно повторить проверки. Только после этого
change можно интегрировать, коммитить и отправлять в `main`. OpenCode намеренно
не имеет разрешения на эти операции.

Если модель зациклилась, не увеличивайте задачу и контекст. Остановите сессию,
добавьте в task точный существующий аналог, ожидаемую сигнатуру и одну узкую
команду теста, затем продолжите ту же сессию. Повторная ошибка на архитектурной
границе означает, что контракт нужно вынести в отдельную задачу для более
сильной модели.

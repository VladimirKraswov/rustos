# Проводник RustOS

## Назначение

Проводник — отдельное системное GUI-приложение. Каждый запуск из «Пуска» или
командой `explorer` создаёт новый `WindowId`, отдельное состояние навигации,
selection, страницы, режима просмотра и незавершённого переименования. Закрытие
окна уничтожает объект приложения и освобождает его физические кадры; повторный
запуск не восстанавливает старое состояние окна.

Окно построено на `rustos-system-ui`: toolbar, read-only path field, sidebar,
Grid/ListView, status bar и оба popup являются обычными компонентами. Hit-test,
hover, focus, pointer capture и команды выполняет общий runtime. Проводник не
хранит второй набор «ручных» прямоугольников для кнопок и файлов.

## Интерфейс

Слева расположены стабильные точки быстрого доступа:

- «Домой» — `/home/user`;
- «Этот компьютер» — `/`;
- «Загрузка» — read-only initramfs `/boot`;
- «Система» — `/system`;
- «Исходники» — `/src`.

Toolbar содержит переход назад и вверх, текущий абсолютный путь, создание
папки, копирование, вставку, удаление и переключатель представления. Доступны:

- сетка крупных системных иконок;
- компактный список;
- таблица с типом и размером файла.

Каталог bootstrap VFS ограничен 32 entries. Проводник не рисует элементы за
границами окна: видимая часть разбивается на страницы, а «Назад»/«Далее» в
status bar меняют страницу. Это ранняя bounded-версия будущей виртуализации
списка по scroll offset.

## Файловые операции

Левая кнопка выбирает объект. Двойной клик по иконке папки открывает её, как в
Windows. Двойной клик по области имени включает inline rename; тот же режим
доступен через контекстное меню. `Enter` подтверждает имя, `Esc` отменяет,
`Backspace` удаляет последний UTF-8 символ. На текущем PS/2 keyboard layout
ввод новых символов ограничен печатным ASCII, но существующие русские имена
отображаются и удаляются корректно.

Правая кнопка внутри файловой области открывает component `Menu`. Пункт
«Создать» открывает дочернее popup с папкой и `.txt`-файлом. Также доступны:

- копировать;
- вырезать;
- вставить;
- переименовать;
- удалить.

Вставка после «Вырезать» использует атомарный `rename`, поэтому является
перемещением без копирования содержимого. Обычная вставка копирует файл или
дерево каталогов bounded FIFO-обходом. Удаление каталога рекурсивно. Если имя
занято, Проводник подбирает безопасное имя копии. `/boot` остаётся read-only:
недопустимые команды disabled заранее и повторно проверяются VFS.

## Граница VFS и микроядра

Сейчас GUI-приложения bootstrap-среза исполняются в адресном пространстве ядра,
но Проводник не обращается к block device и не разбирает VaraniaFS. Он вызывает
общий `BootstrapFs` facade, которым уже пользуется терминал. Поэтому созданные
объекты сразу видны всем окнам и shell-командам, а состояние интерфейса остаётся
приватным для каждого окна.

`BootstrapFs` предоставляет `list/stat/read/write/make_dir/touch`, а для
Проводника добавлены `rename`, `copy_tree` и `remove_tree`. Операции имеют
bounded память; rename валидирует все пути до изменения namespace, а
неудавшееся копирование удаляет только новый destination subtree.

Это переходный backend: writable overlay живёт до выключения и ограничивает
файл 4 KiB. Persistent VaraniaFS уже обслуживается изолированным `vfsd` для
ring-3 программ. Следующий архитектурный шаг — вынести сам Проводник в RUNE/ring
3 и заменить прямой facade тонким клиентом `vfs.dll`; UI и семантика команд при
этом не меняются.

## Ручная проверка

1. Запустите `make run` или `scripts/run.sh`.
2. Откройте «Пуск» → «Проводник» либо введите `explorer` в терминале.
3. В `/home/user` создайте папку и текстовый файл через правую кнопку.
4. Переименуйте объект, скопируйте его, вставьте и затем переместите через
   «Вырезать»/«Вставить».
5. Переключите сетку, список и таблицу.
6. Откройте второй Проводник: файловый namespace будет общим, а выбранный путь
   и selection — независимыми.

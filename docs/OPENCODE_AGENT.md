# Роль OpenCode: один малый модуль RustOS

Работай как исполнитель одного ограниченного change, а не как архитектор всей
ОС. Задание считается корректным только когда в нём перечислены разрешённые
файлы, запрещённые области, критерии приёмки и команды проверки. Если граница
не задана, сначала попроси её уточнить и не редактируй проект.

Перед изменениями:

1. прочитай корневой и ближайший `AGENTS.md` полностью;
2. выполни `git status --short --branch` и перечисли чужие изменения;
3. прочитай указанные в задании документы и существующий код-аналог;
4. коротко зафиксируй, что меняешь и чего не касаешься.

Меняй только файлы из allowlist задания. Каталог `.opencode/**` содержит
локальное состояние и зависимости самого OpenCode: не читай, не редактируй и
не используй его как mirror Todo. Единственный источник текущей задачи — файл,
явно названный пользователем. Не форматируй весь workspace, не
переписывай соседнюю архитектуру, не добавляй dependency без прямой
необходимости. Код и имена — ясные английские, содержательные комментарии и
public docs — русские. Сохраняй `no_std`, bounded memory и проверку ошибок там,
где они уже являются контрактом подсистемы.

Для изменения файлов используй встроенный edit/apply-patch, а не shell
redirection. Не выполняй commit, push, destructive Git-команды, `make clean`,
удаление файлов и команды вне репозитория. Не исправляй уже существующие dirty
files, даже если заметил в них проблему.

После реализации запусти узкие тесты из задания, затем обязательный gate из
ближайшего `AGENTS.md`. В конце выполни `git diff --check` и
`git diff --name-only`. Отчёт обязан содержать: результат, точные команды и их
статус, изменённые файлы, намеренно не затронутую границу и оставшиеся
ограничения. Не называй bootstrap реализацию production-ready.
